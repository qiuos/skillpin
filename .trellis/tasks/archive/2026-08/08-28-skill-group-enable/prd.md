# 技能列表支持技能组启用

## Goal

让技能工作台能够同时呈现单个技能与“技能组”：技能组在列表中以组为单位展示，用户可一键启用整个组，也可打开组弹窗并单独启用其中的技能，从而避免当前只能围绕单个候选技能操作的限制。

## What I already know

* 用户希望技能列表支持“技能组”这一层级：有时整组启用，有时继续下钻后仅启用一个技能。
* 用户期望：列表遇到技能组时按技能组展示；点击技能组打开弹窗；弹窗显示组内技能，并允许单独启用。
* 当前 `/skills` 的目录按 `LocalCatalogGroup` 展示；该结构由同一 `linkName` 的候选项组成，现有列表操作会选择一个候选项并立即调用项目变更接口。
* 当前详情面板已可在同名候选项之间切换，但目录行只显示一个“启用/移除”操作，不能表达“一键启用整组”与“逐项启用”的差异。
* 项目变更接口已经接受多个 `LocalProjectSelectionInput`，因此一次请求可携带多项选择；是否能直接满足“整组”取决于最终确认的技能组语义。

## Assumptions (temporary)

* 已确认：“技能组”按目录结构识别，即一个父目录下包含多个子技能目录（每个子目录有独立 `SKILL.md`）；它不是跨技能源同名冲突的候选项集合。
* 技能组与普通单技能项共用同一份紧凑列表，不分“单个技能 / 技能组”区块；采用已确认的方案 A：组图标、描述前缀、整组操作文案和轻量行底纹/左边框组合区分。
* 点击组名打开组弹窗；弹窗中每个子技能都有独立启用/移除操作，且另有整组启用/移除入口。

## Requirements (evolving)

* 技能组按“父目录直接包含多个子技能目录”的规则识别；在嵌套目录中使用最靠近技能的父目录作为组名。仅因包含下级目录而不直接包含多个技能的外层目录不显示为技能组。例如 `工程开发/前端开发/{UI设计, React开发}` 显示“前端开发”，不显示“工程开发”。
* 同名候选项冲突保持为既有的来源选择语义，不能误作技能组。
* 技能列表同时支持普通单技能项和技能组项，二者均保持紧凑的单行列表样式。
* 技能组的数量与启用状态放在该行的描述中，例如“技能组 · 包含 3 个技能 · 1 / 3 已启用”。
* 技能组须使用非纯颜色的视觉线索与单个技能区分，保证快速扫描和无障碍辨识：使用 `▣` 组图标、“技能组”描述前缀、整组操作文案，并附加轻量底纹或左边框。
* 技能组项提供整组启用能力。
* 点击技能组可打开弹窗查看组内技能。
* 弹窗中支持逐个启用或移除子技能。

## Acceptance Criteria (evolving)

* [ ] 目录中一个父目录直接包含多个子技能时，该目录被识别为一个技能组；嵌套目录时使用最靠近技能的父目录作为组名；同名候选项冲突不被误识别为技能组。
* [ ] 列表可清晰区分单个技能与技能组，且每项均只占一行。
* [ ] 技能组的数量与启用状态显示在该行描述中，不额外占用行或列。
* [ ] 用户可从技能组行一键启用组内全部技能。
* [ ] 用户可打开技能组弹窗，并对组内单个技能执行启用/移除。
* [ ] 组内技能的状态与项目当前链接状态一致，操作后的状态会刷新。
* [ ] 交互具有键盘可访问性，弹窗关闭后焦点返回触发的技能组。

## Decision (ADR-lite)

**Context**：技能组和单个技能需要共用紧凑的一行列表，但用户必须能快速辨识组入口并理解其可进行批量操作。现有的同名候选项集合是来源冲突处理，不代表用户所说的技能组。

**Decision**：技能组按“父目录直接包含多个子技能目录（每个有独立 `SKILL.md`）”识别。遇到嵌套目录时，使用最靠近这些子技能的父目录作为技能组；仅包含下级目录的外层目录不作为组显示。例如 `工程开发/前端开发/{UI设计, React开发}` 显示“前端开发”。采用方案 A：技能组行使用 `▣` 图标；描述以“技能组 · 包含 N 个技能 · X / N 已启用”呈现；右侧提供与整组相关的操作文案；并以轻量行底纹或左边框提供辅助视觉线索。单个技能继续使用普通技能图标与单项操作。

**Consequences**：不增加额外列、标签或分组区块，保持当前虚拟化列表的一行密度；组类型可由图标、文字和操作共同辨识，不依赖颜色。目录层级需要被安全地转换为新的目录型组模型，而不是复用同名冲突模型；外层目录不会与内层组重复展示同一批技能。

## Technical Approach

1. 在核心目录扫描结果之上，根据每个候选技能的相对目录路径构建目录型技能组；仅将直接包含多个技能根目录的最近父目录提升为组，保留现有同名候选项冲突处理。
2. 扩展本地目录 API，使前端可区分单个技能项和目录型技能组，并携带组内候选技能所需的安全摘要数据。
3. 在技能工作台的虚拟化列表中渲染单行组入口；组行点击打开可访问弹窗，批量操作以一组项目选择在一次计划/应用流程中执行；单项操作复用现有直接变更路径。
4. 为目录组识别、批量选择、组弹窗、逐项操作、状态刷新、键盘关闭/焦点回归补充单元与 Playwright 覆盖。

## Technical Notes

* 初步相关文件：`packages/web/src/features/catalog/skills-workbench-page.tsx`、`packages/core/src/api/contracts.ts`、`packages/cli/src/session/source-runtime.ts`、`packages/core/src/catalog/catalog-snapshot.ts`、`tests/e2e/app.spec.ts`。
* 当前 `LocalCatalogGroup` 是同一 `linkName` 下的候选技能集合；它解决的是跨技能源同名冲突，不等同于按目录组织的“技能组”。
* 扫描器会递归扫描目录，但只要某目录自身含有 `SKILL.md` 就停止继续向下扫描。因此可将“自身不是技能、其下包含多个可发现技能的目录”作为目录型技能组的候选判定；最终规则仍待用户确认。
