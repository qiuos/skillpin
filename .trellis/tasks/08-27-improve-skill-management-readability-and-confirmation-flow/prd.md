# 改善技能管理可读性与确认流程

## Goal

让技能管理界面的文字达到当前操作按钮同等的可读性，并把技能启用/移除操作调整为直接、易理解且仅保留一次最终确认的安全流程。

## What I already know

- 用户反馈除操作按钮外的文本普遍过小，难以阅读；希望以现有操作按钮的字号作为正文字号基准，并同步调整布局与视觉层级。
- 用户要求已启用技能能够移除。
- 用户要求“启用”不再进入审查界面，而是直接弹出一次确认对话框；确认文案需要简洁直白。
- 现有工作台位于 `packages/web/src/features/catalog/skills-workbench-page.tsx`，技能行的复选框已可为已启用项目暂存移除意图，但缺少直观的“移除”语义。
- 当前启用流程为：暂存 → “启用” → “审查项目变更”对话框 → “确认项目变更”对话框 → 应用；需删除中间审查界面，但保留服务端计划、事务、版本校验与最终确认后的安全应用。
- `packages/web/src/styles.css` 的多处信息文字使用 `--font-small`（15px），而通用操作按钮继承 `--font-ui`（16px）；本次将技能管理主要可见文字至少提升至操作按钮级别，并重新平衡行高、面板间距和列表行高度。

## Requirements

- 将技能管理工作台中的主要可见文本（筛选、来源标签、技能列表名称/摘要/状态、详情元数据、候选来源、命令栏、弹窗与辅助提示）提高到与现有操作按钮相当的字号；保留仅在确有必要的紧凑辅助信息中使用更小字号。
- 调整技能工作台的行高、列表行高、面板内边距、筛选/来源控件和响应式布局，使放大后的文字不截断、不拥挤，并在窄视图中仍可访问。
- 对未启用技能，保留明确的“启用”暂存入口；对已启用技能，提供明确的“移除”入口，并在应用前仍由浏览器本地暂存、服务端计划和最终确认保护，不能直接修改文件系统。
- 点击主操作后仍先向服务端生成最新计划以保留阻塞校验；计划无阻塞时直接打开唯一的确认弹窗，不显示可编辑的审查/变更明细对话框。
- 确认弹窗使用简洁直白的中文：明确说明“将启用/移除 N 个技能”，提供“取消”和对应的最终操作按钮；加载状态同样简洁。
- 计划被阻塞或生成失败时不打开确认弹窗，继续展示明确错误并保留用户暂存选择。
- 更新 Playwright 覆盖，以验证启用和移除流程均只出现一次确认对话框、没有“审查项目变更”对话框、确认后请求仍安全执行。
- 更新前端 Trellis 规范，记录单次确认及明确启用/移除入口的新交互约定。

## Acceptance Criteria

- [ ] 在技能工作台常见桌面尺寸下，除极少数紧凑辅助内容外，主要信息文字不小于操作按钮文字，并且列表、筛选、详情和弹窗均无明显裁切或重叠。
- [ ] 已启用技能有清晰可发现的“移除”操作；未启用技能有清晰可发现的“启用”操作；两者均只暂存意图，未确认前不改变项目文件。
- [ ] 点击启用或移除后的流程只展示一个最终确认对话框；界面中不再出现“审查项目变更”。
- [ ] 确认对话框能以简洁文案准确提示本次启用/移除数量；取消不应用，确认后仍调用既有事务 API。
- [ ] 被服务端阻塞的计划不能进入确认；错误后暂存选择保留。
- [ ] 格式检查、lint、typecheck、构建、单元/集成测试及 E2E 测试通过。

## Definition of Done

- 已更新适用的前端/E2E 测试和前端规范。
- 不改变后端文件系统事务、鉴权、版本冲突、幂等或恢复语义。
- 通过项目质量门禁。

## Technical Approach

1. 在技能行中以明确的操作按钮取代含义不直观的复选框：未启用时“启用”，已启用时“移除”；按钮仅更新本地 staged state。
2. 主操作仍请求 `projectPlan()`，但成功且无阻塞时直接保存计划并打开唯一确认弹窗；最终确认使用原有 `applyProjectChanges()` 调用与新 request ID。
3. 由计划 changes 推导启用/移除数量和最终按钮/文案；若存在混合变更，文案同时列出两类数量。
4. 集中提升工作台正文 token 的实际使用点，并重新调整各面板、行和控件尺寸，避免大字带来的溢出。
5. 同步更新 P9 前端交互契约与 Playwright 断言。

## Decision (ADR-lite)

**Context**: 两层“审查→确认”对用户而言冗余且文案抽象；复选框不清楚地表达已启用技能可被移除。文字层级也没有满足桌面端可读性需求。

**Decision**: 保留后台生成计划、阻塞校验和最终确认的安全边界，移除用户可见的审查步骤。通过显式“启用”/“移除”按钮表达暂存意图，并将确认信息聚焦在本次真正会执行的动作和数量。

**Consequences**: 用户操作更短、更清楚；仍依赖服务器计划与现有事务保证安全。需更新既有 P9 的“两步交互”规范和 E2E 用例。

## Out of Scope

- 修改后端项目链接/事务实现、权限或恢复策略。
- 全应用的品牌重设计，或非技能管理页面的大规模文案改写。
- 增加批量选择之外的新项目管理功能。
